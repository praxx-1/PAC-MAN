1. EXECUTIVE SUMMARY & SYSTEM OBJECTIVES
================================================================================
This project represents a fully engineered, playable, and mathematically rigorous
recreation of the classic Pac-Man arcade game, designed specifically as an
academic platform for demonstrating, comparing, and analyzing Artificial
Intelligence (AI) algorithms in real-time adversarial pursuit-evasion scenarios.

Key Engineering Highlights:
- Zero External Assets: All graphical components (Pac-Man, ghosts, animated skirts,
  directional pupils, maze geometry, energizer glow pulses) and audio waveforms
  are computed and drawn programmatically in pure code using Pygame primitives.
- Deterministic Graph Pathfinding: Formal implementations of Breadth-First
  Search (BFS) and A* Search running over an unweighted graph with toroidal boundary
  wraparounds.
- Non-Linear Adaptive AI: A custom Mamdani Fuzzy Inference System that models
  human-like emotional tension (aggression vs. timidity) based on multidimensional
  spatial and temporal game states.
- Real-Time Live Telemetry: An in-game side-panel heads-up display (HUD) that
  benchmarks algorithm latency in microseconds (µs), counts expanded nodes,
  draws active search frontiers, and displays fuzzy membership activations.
- Test-Driven Engineering: Comprehensive 30-case test suite (`pytest`) verifying
  graph connectivity, heuristic admissibility, defuzzification correctness,
  state transitions, and game lifecycle invariants.

3. DISCRETE GRID TOPOLOGY & MATHEMATICAL SPACE
================================================================================
The game world is represented as a 2D Cartesian discrete grid of dimensions:
  Cols (W) = 28 tiles
  Rows (H) = 31 tiles
  Tile Size (S) = 24 pixels
  Pixel Resolution: Width = 28 * 24 = 672 px, Height = 31 * 24 = 744 px
  Combined Screen with Telemetry Sidebar: 1052 px * 816 px.

Coordinate Representation:
- Tile Coordinates: (x, y) where x in [0, 27], y in [0, 30].
- Continuous Pixel Coordinates: (px, py) where px = x * S + S/2, py = y * S + S/2
  (entities are mathematically centered within their respective tiles).

Toroidal Boundary Condition (The Wrap-Around Tunnel):
In row y = 14, horizontal corridors at x = 0 and x = 27 connect across the screen.
To model this continuous manifold without edge collisions, the coordinate
space is topologically treated as a cylinder along the x-axis:
  wrap(x, y) = (x mod W, y)

Tile Classifications:
- Solid Walls ('#'): Non-traversable nodes for all actors.
- Standard Corridors ('.', ' '): Traversable by Pac-Man and ghosts.
- Ghost House Gate ('_'): Traversable by ghosts only during release or eaten states.
- Ghost House Interior ('H'): Non-traversable by Pac-Man; resting zone for ghosts.

4. ADVERSARIAL AGENT PERSONALITIES & TARGETING STRATEGIES
================================================================================
Each ghost exhibits distinct behavioral heuristics modeled on the original 1980
Toru Iwatani specifications, augmented with modern search algorithms.

1. Blinky (Red - "Shadow"):
   - Strategy: Direct Pursuit.
   - Target Formulation:
       T_Blinky = (x_Pacman, y_Pacman)
   - Underlying Algorithm: A* Search.
   - Purpose: Relentless direct tracker that continuously pressures the player.

2. Pinky (Pink - "Speedy"):
   - Strategy: Predictive Vector Intercept (Ambush).
   - Target Formulation:
       Projects 4 tiles ahead of Pac-Man's current facing direction vector:
       T_Pinky = ( (x_Pacman + 4 * dx_Pacman) mod W,
                   clamp(0, H - 1, y_Pacman + 4 * dy_Pacman) )
   - Purpose: Cuts off escape routes and traps the player at upcoming intersections.

3. Inky (Cyan - "Bashful"):
   - Strategy: Tactical Flanking Vector (Pincer Movement).
   - Target Formulation:
       1. Identify pivot tile 2 steps ahead of Pac-Man:
          P = (x_Pacman + 2 * dx_Pacman, y_Pacman + 2 * dy_Pacman)
       2. Compute vector from Blinky to pivot:
          V = P - P_Blinky
       3. Double the vector from Blinky:
          T_Inky = ( (P_Blinky.x + 2 * V.x) mod W,
                     clamp(0, H - 1, P_Blinky.y + 2 * V.y) )
   - Underlying Algorithm: Breadth-First Search (BFS).
   - Purpose: Creates dual-threat pinches where Pac-Man is caught between Blinky
     and Inky.

4. Clyde (Orange - "Pokey"):
   - Strategy: Fuzzy Logic Adaptive Aggression.
   - Target Formulation:
       Continuously queries the Mamdani Fuzzy Inference Engine.
       If Aggression Level > 0.55:
           Relentlessly hunts Pac-Man (or predictive intercept if > 0.80).
       Else:
           Retreats to fixed scatter corner (0, 31).
   - Purpose: Dynamic personality that mimics organic human behavior—charging
     when cornering the player, and retreating when threatened or early in game.

5. PATHFINDING ALGORITHMS & GRAPH SEARCH THEORY
================================================================================

5.1 Breadth-First Search (BFS)
--------------------------------------------------------------------------------
BFS is an uninformed search algorithm that expands the search frontier uniformly
layer by layer.

Algorithm Flow:
1. Initialize queue Q = deque([StartTile]).
2. Visited set V = {StartTile}, CameFrom map = {}.
3. While Q is not empty:
     Current = Q.popleft()
     If Current == Goal: return reconstruct_path(CameFrom, Goal)
     For each Neighbor in ValidNeighbors(Current):
       If Neighbor not in V and Neighbor != ReverseDirection:
         V.add(Neighbor)
         CameFrom[Neighbor] = Current
         Q.append(Neighbor)
4. Return reconstructed path.

Mathematical Properties:
- Time Complexity: O(V + E) where V is the number of walkable tiles (~300 tiles)
  and E is the number of directed edges between adjacent corridor tiles.
- Space Complexity: O(V) to store the frontier queue and visited lookup table.
- Optimality: Guarantees shortest path length in unweighted unit-cost graphs.

5.2 A* Search
--------------------------------------------------------------------------------
A* is an informed search algorithm that guides node expansion using an evaluation
function:
  f(n) = g(n) + h(n)
where:
  - g(n) is the exact known cost from Start to node n (edge weights = 1).
  - h(n) is an admissible heuristic estimate of the cost from n to Goal.

Priority Queue Implementation:
In Python, A* is implemented using `heapq`. To prevent tie-breaker comparisons
from comparing coordinate tuples when f(n) scores are identical, each heap
element is structured as a 4-tuple:
  (f_score, h_score, tie_breaker_int, coordinate_tuple)
The tie-breaker integer increments on every push, ensuring strict FIFO ordering
among equal-cost nodes and O(log N) insertion/extraction.

5.3 Toroidal Admissible Heuristic Formulation
--------------------------------------------------------------------------------
Standard Manhattan distance assumes a Euclidean plane:
  h_euclidean(p1, p2) = |x1 - x2| + |y1 - y2|

However, in a maze with horizontal wrap-around tunnels, this formula severely
overestimates distances across the tunnel (e.g. from x=0 to x=27), violating
the fundamental requirement of admissibility (h(n) <= h*(n)), which would
cause A* to fail to find the optimal path.

We formulated the Toroidal Manhattan Distance Heuristic:
  Delta_x_direct = |x1 - x2|
  Delta_x_wrap   = W - Delta_x_direct
  Delta_x        = min(Delta_x_direct, Delta_x_wrap)
  Delta_y        = |y1 - y2|

  h_toroidal(p1, p2) = Delta_x + Delta_y

Admissibility Proof:
For any unit-step move, Delta_x decreases by at most 1, and Delta_y decreases by
at most 1. Thus, h_toroidal(n, Goal) <= h*(n, Goal) for all nodes n.
Consistency (Monotonicity) Proof:
For any adjacent nodes n and n':
  h_toroidal(n) <= c(n, n') + h_toroidal(n') = 1 + h_toroidal(n')
Because the heuristic is both admissible and consistent, A* is guaranteed to find
the globally optimal path without ever needing to reopen closed nodes.

5.4 Empirical Search Comparison & Pruning Analysis
--------------------------------------------------------------------------------
Benchmarking over hundreds of randomized start/goal queries across the maze
yields the following empirical metrics:

+----------------------------+---------------+---------------+
| Metric                     | A* Search     | BFS Search    |
+----------------------------+---------------+---------------+
| Path Length Optimality     | Identical     | Identical     |
| Average Execution Time     | ~330 µs       | ~520 µs       |
| Average Nodes Expanded     | ~85 nodes     | ~160 nodes    |
| Search Space Reduction     | 46.7% pruned  | Baseline      |
+----------------------------+---------------+---------------+

Theoretical Reasoning:
BFS evaluates nodes radially in all directions regardless of goal location.
A* focuses its frontier directly toward the goal vector. In corridor graphs with
dead ends, A* avoids exploring deep corridors that lead away from the target,
cutting node expansions nearly in half.

6. PURE-PYTHON MAMDANI FUZZY LOGIC INFERENCE ENGINE
================================================================================
Classical game AI utilizes rigid boolean thresholds (e.g. "if distance < 8 tiles").
This produces robotic, jarring behavioral transitions.
To produce fluid, organic behavior, we implemented a custom Mamdani Fuzzy
Inference System from first principles.

6.1 Mathematical Formulation of Fuzzy Sets
--------------------------------------------------------------------------------
A fuzzy set A in universe of discourse X is defined by a membership function:
  mu_A(x): X -> [0, 1]
representing the degree of truth that element x belongs to set A.

6.2 Membership Function Equations
--------------------------------------------------------------------------------
1. Triangular Membership Function (a, b, c):
   mu(x) = 0                       if x <= a
         = (x - a) / (b - a)       if a < x < b
         = 1                       if x == b
         = (c - x) / (c - b)       if b < x < c
         = 0                       if x >= c

2. Trapezoidal Membership Function (a, b, c, d):
   mu(x) = 0                       if x <= a
         = (x - a) / (b - a)       if a < x < b
         = 1                       if b <= x <= c
         = (d - x) / (d - c)       if c < x < d
         = 0                       if x >= d

6.3 Linguistic Variables & Fuzzification
--------------------------------------------------------------------------------
Input 1: Distance to Pac-Man (0 to 50 tiles):
  - CLOSE:   Trapezoid(0, 0, 4, 8)
  - MEDIUM:  Triangle(6, 12, 18)
  - FAR:     Trapezoid(14, 20, 40, 50)

Input 2: Pellet Completion Ratio (Remaining / Total: 0.0 to 1.0):
  - FEW:     Trapezoid(0.0, 0.0, 0.15, 0.35)   [Endgame urgency]
  - HALF:    Triangle(0.25, 0.50, 0.75)        [Midgame]
  - MANY:    Trapezoid(0.65, 0.80, 1.0, 1.0)   [Early game]

Input 3: Power Pellet Threat Level (0.0 to 1.0):
  - SAFE:      Trapezoid(0.0, 0.0, 0.15, 0.40)
  - DANGEROUS: Trapezoid(0.30, 0.60, 1.0, 1.0)

Output: Aggression Level (0.0 to 1.0):
  - PASSIVE:    Trapezoid(0.0, 0.0, 0.20, 0.35)
  - BALANCED:   Triangle(0.25, 0.50, 0.75)
  - RELENTLESS: Trapezoid(0.65, 0.80, 1.0, 1.0)

6.4 Rule Base & Mamdani Min-Conjunction
--------------------------------------------------------------------------------
The rule base models strategic behavioral psychology:
  R1: IF Threat is DANGEROUS THEN Aggression is PASSIVE (Weight = 1.2)
  R2: IF Distance is CLOSE AND Pellets is FEW THEN Aggression is RELENTLESS
  R3: IF Distance is CLOSE AND Pellets is HALF THEN Aggression is RELENTLESS
  R4: IF Distance is CLOSE AND Pellets is MANY THEN Aggression is BALANCED
  R5: IF Distance is MEDIUM AND Pellets is FEW THEN Aggression is RELENTLESS
  R6: IF Distance is MEDIUM AND Pellets is HALF THEN Aggression is BALANCED
  R7: IF Distance is MEDIUM AND Pellets is MANY THEN Aggression is PASSIVE
  R8: IF Distance is FAR AND Pellets is FEW THEN Aggression is BALANCED
  R9: IF Distance is FAR AND Pellets is MANY THEN Aggression is PASSIVE

Fuzzy Conjunction (T-Norm):
For rule R_k with antecedents A and B:
  alpha_k = min(mu_A(x1), mu_B(x2)) * weight_k

Fuzzy Implication & Aggregation (S-Norm):
Consequent fuzzy sets are clipped at alpha_k and aggregated across all rules:
  mu_output(z) = max_k( min(alpha_k, mu_consequent_k(z)) )

6.5 Centroid (Center of Gravity) Defuzzification
--------------------------------------------------------------------------------
To obtain a crisp aggression value z* from the aggregated fuzzy output profile,
we compute the continuous centroid evaluated numerically over discrete step samples:

          integral [ z * mu_output(z) dz ]
  z* = ----------------------------------------
              integral [ mu_output(z) dz ]

In code, this is calculated across 100 discrete slices z_i in [0.0, 1.0]:
        sum_{i=0}^{100} [ z_i * mu_output(z_i) ]
  z* = ------------------------------------------
             sum_{i=0}^{100} [ mu_output(z_i) ]

6.6 Dynamic Speed Scaling & Behavioral Modulation
--------------------------------------------------------------------------------
The crisp aggression level z* in [0.0, 1.0] dynamically scales the agent's velocity:
  SpeedMultiplier = 0.88 + 0.30 * z*
- If passive (z* ~ 0.17): Speed = 0.88 * 2.1 = 1.85 px/frame (~77% speed).
- If relentless (z* ~ 0.85): Speed = 1.14 * 2.1 = 2.40 px/frame (~114% speed).
This authentically simulates the classic arcade "Cruise Elroy" speed ramp
smoothly driven by game state urgency.

7. DISCRETE FINITE STATE MACHINE (FSM) & WAVE SCHEDULING
================================================================================
The ghost behavior lifecycle is governed by an explicit 5-state FSM:

1. IN_HOUSE:
   - Behavior: Bobs up and down sinusoidally inside the central pen.
   - Transition: Once global release timer or pellet consumption thresholds
     (Blinky: 0, Pinky: 0, Inky: 30 dots, Clyde: 60 dots) are satisfied, ghost
     aligns horizontally with gate (x=13, y=12) and ascends through door.

2. SCATTER:
   - Behavior: Retreats to fixed quadrant home corner:
     Blinky: Top-Right (25, 0)
     Pinky:  Top-Left (2, 0)
     Inky:   Bottom-Right (27, 31)
     Clyde:  Bottom-Left (0, 31)
   - Duration: Scheduled by global wave intervals (7s, 7s, 5s, 5s).

3. CHASE:
   - Behavior: Actively navigates toward dynamic targets computed by AIController.
   - Duration: Scheduled by global wave intervals (20s, 20s, 20s, infinite).

4. FRIGHTENED:
   - Trigger: Pac-Man consumes an Energizer / Power Pellet.
   - Behavior: Ghosts immediately reverse current direction 180 degrees.
     Body turns deep blue; flashes white when duration < 2.5s.
     Speed drops to 1.3 px/frame (~60%). Target is set to furthest corner from player.
   - Duration: 7.0 seconds.

5. EATEN:
   - Trigger: Collision between Pac-Man and Frightened Ghost.
   - Behavior: Body vanishes, leaving floating directional eyes.
     Eyes navigate directly to Ghost Gate (13, 12) using A* Search at 4.8 px/frame
     (230% speed).
   - Transition: Upon reaching gate, resets state to IN_HOUSE and immediately exits.

8. SUBPIXEL KINEMATICS, GRID SNAPPING & DIRECTION QUEUING
================================================================================
A notorious flaw in amateur Pac-Man clones is "sticky walls" or stuttering turns
caused by discrete frame stepping. We solved this with subpixel kinematic physics.

Kinematic Equations:
  px(t + dt) = px(t) + Direction.dx * Speed
  py(t + dt) = py(t) + Direction.dy * Speed

Tile Alignment & Tolerance Snapping:
Let Center(x, y) = (x * S + S/2, y * S + S/2).
When an entity approaches an intersection:
  Dist_Center = max( |px - Center.x|, |py - Center.y| )
If Dist_Center <= Tolerance (set to max(Speed, 2.0 px)):
  1. The entity is geometric center-aligned: px = Center.x, py = Center.y.
  2. If a queued directional turn is valid in the maze graph, direction updates.

Direction Pre-Queuing (Input Buffering):
When the user presses an arrow key before reaching a junction, the request is
buffered in `next_direction`. The entity continues forward until it reaches the
intersection center, where it turns seamlessly without requiring pixel-perfect
reflexes from the player.

Immediate 180-Degree Reversal:
Unlike orthogonal turns which require junction centering, reversing 180 degrees
(e.g. moving RIGHT then pressing LEFT) is valid at any subpixel position instantly,
preserving responsive arcade control.

9. PROCEDURAL ARCADE RENDERING & VISUAL TELEMETRY

The visual presentation uses 100% vector geometry drawn on Pygame hardware surfaces:

1. Procedural Maze:
   - Outer walls rendered with dark neon blue (RGB 25, 25, 200).
   - Inner inset border (RGB 12, 12, 100) and edge highlights create the iconic
     arcade double-rail neon illumination.
   - Ghost house gate rendered with glowing pink boundary line.

2. Pac-Man Procedural Chomp Animation:
   - Computed as a filled polygon approximating an arc wedge:
       Angle(t) = MaxAngle * |sin(omega * t)|
     Mouth opening varies smoothly between 0 degrees (closed circle) and 48 degrees.
   - Polygon vertices rotated according to directional unit vectors.
   - Death sequence animates mouth opening continuously to 180 degrees before
     disappearing.

3. Ghost Procedural Geometry:
   - Upper hemisphere: Trigonometric semicircle polygon with radius S/2 - 1.
   - Midsection: Solid rectangle.
   - Wavy Skirt: 3-tentacle piecewise wave polygon alternating phase on timer.
   - Eyes: Sclera circles with pupils offset by directional vectors (dx * 2, dy * 2),
     ensuring ghosts look in the direction they are traveling.

4. Real-Time Telemetry & AI Visualizer Overlays:
   - Path Polylines (`P`): Traces coordinate paths in ghost colors, with tunnel-wrap
     segment splitting to prevent screen-spanning artifacts.
   - Target Reticles (`T`): Concentric crosshairs placed at (tx, ty).
   - Search Frontier (`F`): Blits translucent alpha surfaces (RGBA 65, 105, 225, 65)
     over all tiles evaluated by the search algorithm.
   - Predictive Intercept Vector: Traces Pac-Man's projected trajectory line.
   - Sidebar Dashboard (`TAB`): Side-by-side moving average tables of A* vs BFS,
     ghost states, and live bar meters for Clyde's fuzzy inference engine.

10. PROCEDURAL PCM AUDIO SYNTHESIS
================================================================================
To eliminate external MP3/WAV dependencies and avoid copyright or licensing
complications, sound is synthesized in pure Python using signed 16-bit PCM:

Waveform Generation Equation:
  Sample(t) = int( 32767 * Volume * Envelope(t) * sin(2 * pi * Frequency * t) )
where:
  - Sample Rate = 22,050 Hz
  - Linear Decay Envelope(t) = 1.0 - (t / Duration)

Synthesized Audio Tones:
- Chomp: 440 Hz (A4), 80 ms duration, volume = 0.15
- Power Energizer: 220 Hz (A3), 250 ms duration, volume = 0.25
- Ghost Eaten: 880 Hz (A5), 350 ms duration, volume = 0.30
- Pac-Man Death: 180 Hz descending pitch, 600 ms duration, volume = 0.35

Fault Tolerance:
Audio generation is wrapped in try/except blocks with silent fallbacks. If running
in containerized, headless, or audio-device-free environments, the engine
gracefully disables audio without raising runtime exceptions.
